## Day 12 - Webpack 核心构建基建 (3.16，周一，3h)

> **今日策略**：深入理解 Webpack 的构建流程和插件机制，这是前端工程化的基础。同时掌握 Tree-shaking 的底层原理，这是优化打包体积的关键。

### 1. Webpack 核心概念：入口、出口、Loader、Plugin

#### 1.1 Webpack 是什么？

**定义**：Webpack 是一个模块打包器（Module Bundler），它把项目中的所有资源（JS、CSS、图片等）当作模块，通过依赖关系打包成一个或多个 bundle。

**核心思想**：
- **一切皆模块**：JS、CSS、图片、字体等都是模块
- **依赖关系**：通过 `import/require` 建立依赖关系
- **打包输出**：把所有模块打包成浏览器可以运行的代码

#### 1.2 四个核心概念

**1. Entry（入口）**

指定 Webpack 从哪个文件开始打包：

```javascript
// webpack.config.js
module.exports = {
  entry: './src/index.js', // 单入口
  // 或者
  entry: {
    main: './src/index.js',
    vendor: './src/vendor.js'
  } // 多入口
};
```

**2. Output（出口）**

指定打包后的文件输出位置：

```javascript
module.exports = {
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'bundle.js'
    // 或者多入口时
    // filename: '[name].[hash].js'
  }
};
```

**3. Loader（加载器）**

处理非 JS 文件（如 CSS、图片、TypeScript）：

```javascript
module.exports = {
  module: {
    rules: [
      {
        test: /\.css$/, // 匹配 .css 文件
        use: ['style-loader', 'css-loader'] // 从右到左执行
      },
      {
        test: /\.ts$/,
        use: 'ts-loader'
      }
    ]
  }
};
```

**Loader 的执行顺序**：从右到左（或从下到上）
```javascript
use: ['style-loader', 'css-loader']
// 执行顺序：css-loader → style-loader
```

**4. Plugin（插件）**

在打包过程的特定时机执行任务（如压缩、提取 CSS、生成 HTML）：

```javascript
const HtmlWebpackPlugin = require('html-webpack-plugin');

module.exports = {
  plugins: [
    new HtmlWebpackPlugin({
      template: './src/index.html'
    })
  ]
};
```

**Loader vs Plugin**：
- **Loader**：处理单个文件（转换、编译）
- **Plugin**：处理整个打包过程（优化、提取、生成文件）

### 2. 手写自定义 Loader 和 Plugin

#### 2.1 手写自定义 Loader：MD 转 Vue 组件

**需求**：把 Markdown 文件转换成 Vue 组件。

**实现**：

```javascript
// my-md-loader.js
const marked = require('marked');

module.exports = function(source) {
  // source 是 Markdown 文件的内容
  
  // 1. 把 Markdown 转换成 HTML
  const html = marked(source);
  
  // 2. 包装成 Vue 组件
  const vueComponent = `
    <template>
      <div class="markdown-body">
        ${html}
      </div>
    </template>
    <script>
    export default {
      name: 'MarkdownComponent'
    }
    </script>
    <style scoped>
    .markdown-body {
      /* 样式 */
    }
    </style>
  `;
  
  // 3. 返回 Vue 组件代码
  return vueComponent;
};
```

**使用**：

```javascript
// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.md$/,
        use: './my-md-loader.js'
      }
    ]
  }
};
```

**Loader 的本质**：
- 是一个函数，接收源文件内容，返回转换后的代码
- 可以链式调用（多个 Loader 串联）

#### 2.2 手写自定义 Plugin：打包后自动上传 CDN

**需求**：打包完成后，自动把文件上传到 CDN。

**实现**：

```javascript
// upload-cdn-plugin.js
const fs = require('fs');
const path = require('path');

class UploadCDNPlugin {
  constructor(options) {
    this.options = options; // { cdnUrl: 'https://cdn.example.com' }
  }
  
  apply(compiler) {
    // 在打包完成后执行
    compiler.hooks.afterEmit.tap('UploadCDNPlugin', (compilation) => {
      const outputPath = compilation.options.output.path;
      const files = compilation.assets;
      
      // 遍历所有输出文件
      Object.keys(files).forEach(filename => {
        const filePath = path.join(outputPath, filename);
        
        // 上传到 CDN（伪代码）
        this.uploadToCDN(filePath, filename);
      });
    });
  }
  
  uploadToCDN(filePath, filename) {
    // 实际上传逻辑（使用 axios 或其他 HTTP 客户端）
    console.log(`上传 ${filename} 到 CDN...`);
    // axios.post(this.options.cdnUrl, fs.readFileSync(filePath))
  }
}

module.exports = UploadCDNPlugin;
```

**使用**：

```javascript
// webpack.config.js
const UploadCDNPlugin = require('./upload-cdn-plugin');

module.exports = {
  plugins: [
    new UploadCDNPlugin({
      cdnUrl: 'https://cdn.example.com'
    })
  ]
};
```

**Plugin 的本质**：
- 是一个类，必须有 `apply` 方法
- 通过 `compiler.hooks` 在特定时机执行任务
- 可以访问整个编译过程

### 3. Tree-shaking 底层原理：AST 分析

#### 3.1 什么是 Tree-shaking？

**定义**：Tree-shaking 是一种死代码消除（Dead Code Elimination）技术，移除未使用的代码。

**前提条件**：
- 使用 ES6 模块（`import/export`）
- 开启生产模式（`mode: 'production'`）

#### 3.2 Tree-shaking 的工作原理

**步骤 1：标记未使用的代码**

```javascript
// utils.js
export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}

// index.js
import { add } from './utils';
console.log(add(1, 2));
// subtract 没有被使用，会被标记为"未使用"
```

**步骤 2：AST 分析**

Webpack 使用 AST（抽象语法树）分析代码：

```javascript
// AST 分析过程（简化版）
1. 解析 import 语句，找到所有导入的模块
2. 遍历每个模块的 AST，标记哪些 export 被使用了
3. 删除未使用的 export
```

**步骤 3：删除未使用的代码**

```javascript
// 打包后的代码（简化版）
// utils.js 中的 subtract 函数被删除了
function add(a, b) {
  return a + b;
}
```

#### 3.3 `sideEffects` 的作用

**问题**：有些模块虽然没有被直接使用，但可能有副作用（如 CSS 导入、polyfill）。

```javascript
// index.js
import './styles.css'; // 这个导入没有返回值，但有副作用（加载样式）
import 'core-js/stable'; // 有副作用（polyfill）
```

**解决方案**：在 `package.json` 中声明 `sideEffects`：

```json
{
  "sideEffects": [
    "*.css",
    "./src/polyfills.js"
  ]
}
```

**作用**：
- 告诉 Webpack 这些文件有副作用，不要删除
- 如果设为 `false`，表示所有文件都没有副作用，可以更激进地删除代码

### 4. Webpack 构建流程总结

**完整流程**：

```
1. 初始化：读取配置，创建 Compiler 对象
2. 开始编译：调用 compiler.run()
3. 确定入口：从 entry 开始
4. 编译模块：调用 Loader 处理文件
5. 完成编译：得到模块依赖图
6. 输出资源：根据依赖图生成 chunk
7. 完成输出：写入文件系统
```

**关键点**：
- **Loader**：在编译阶段处理文件
- **Plugin**：在构建过程的各个阶段执行任务
- **Tree-shaking**：在生成阶段删除未使用的代码

## Day 13 - 新一代工程化（Vite 与 Babel）(3.17，周二，3h)

> **今日策略**：深入理解 Vite 的冷启动原理和 HMR 机制，这是现代前端工程化的核心。同时掌握 Babel 的编译原理，这是理解前端工具链的基础。

### 1. Vite 核心机制：为什么比 Webpack 快？

#### 1.1 传统构建工具的痛点（Webpack）

**问题场景**：
当你启动一个大型项目时，Webpack 需要：
1. 从入口文件开始，递归分析所有依赖
2. 把所有模块打包成一个或多个 bundle
3. 启动开发服务器

**痛点**：
- **冷启动慢**：项目越大，打包时间越长（可能几分钟）
- **HMR 慢**：修改一个文件，需要重新打包整个模块依赖链
- **开发体验差**：每次修改都要等很久

#### 1.2 Vite 的降维打击：基于 ESM 的冷启动

**核心思想**：利用浏览器原生的 ES Module（ESM）能力，不需要预先打包！

**工作流程**：

```javascript
// 1. 启动开发服务器（秒级启动！）
vite dev

// 2. 浏览器请求 index.html
// <script type="module" src="/src/main.js"></script>

// 3. 浏览器解析到 type="module"，发起请求
GET /src/main.js

// 4. Vite 服务器拦截请求，返回源码（不打包！）
// 如果遇到 import，浏览器会继续发起请求
import { createApp } from 'vue'
// 浏览器自动请求：GET /node_modules/vue/dist/vue.esm-browser.js

// 5. Vite 服务器按需转换（只转换请求的文件）
```

**关键点**：
- **不预先打包**：启动时不做任何打包工作，秒级启动
- **按需转换**：只有浏览器请求的文件才会被转换
- **利用浏览器原生能力**：浏览器自己处理 `import/export`

#### 1.3 预构建（Esbuild）解决了什么问题？

**问题**：虽然浏览器支持 ESM，但有两个问题：

1. **第三方库不是 ESM 格式**：
   ```javascript
   // node_modules/vue 可能是 CommonJS 格式
   module.exports = { ... }
   
   // 浏览器无法直接使用
   ```

2. **大量小文件请求**：
   ```javascript
   // lodash 可能有几百个文件
   import { debounce } from 'lodash'
   // 如果直接使用，会发起几百个 HTTP 请求！
   ```

**解决方案：预构建（Pre-bundling）**

Vite 使用 **Esbuild**（用 Go 写的，比 Webpack 快 10-100 倍）进行预构建：

```javascript
// 1. 第一次启动时，Vite 扫描依赖
// 发现：vue, lodash, axios 等

// 2. 使用 Esbuild 把这些依赖打包成 ESM 格式
// node_modules/vue → node_modules/.vite/vue.js (ESM)
// node_modules/lodash → node_modules/.vite/lodash.js (ESM)

// 3. 浏览器请求时，直接返回预构建的文件
GET /node_modules/.vite/vue.js
```

**为什么用 Esbuild？**
- **速度快**：Go 语言编写，比 JavaScript 快 10-100 倍
- **只用于依赖预构建**：不用于业务代码（因为不支持一些高级特性）

#### 1.4 HMR 热更新机制：为什么比 Webpack 快？

**Webpack HMR 的问题**：
```javascript
// 修改一个文件
// src/components/Button.vue

// Webpack 需要：
// 1. 重新打包整个模块依赖链
// 2. 更新整个 bundle
// 3. 浏览器重新加载
// 耗时：几秒到几十秒
```

**Vite HMR 的优势**：

```javascript
// 修改一个文件
// src/components/Button.vue

// Vite 只需要：
// 1. 只转换这一个文件（Esbuild）
// 2. 通过 WebSocket 推送更新
// 3. 浏览器只更新这个模块
// 耗时：毫秒级！
```

**底层实现**：

```javascript
// 1. Vite 服务器监听文件变化
chokidar.watch('src/**/*.vue')

// 2. 文件变化时，立即转换这个文件
const transformed = esbuild.transform(fileContent)

// 3. 通过 WebSocket 推送更新
ws.send({
  type: 'update',
  path: '/src/components/Button.vue',
  content: transformed.code
})

// 4. 浏览器接收更新，只替换这个模块
// 不需要重新加载整个页面！
```

**关键优势**：
- **精确更新**：只更新变化的模块，不影响其他模块
- **保持状态**：组件状态不会丢失
- **极速响应**：毫秒级更新

### 2. Babel 编译原理：Parse -> Transform -> Generate

#### 2.1 Babel 是什么？

**定义**：Babel 是一个 JavaScript 编译器，把新版本的 JavaScript 代码转换成旧版本（兼容性转换）。

**核心功能**：
- **语法转换**：ES6+ → ES5
- **API 转换**：`Promise`、`Array.from` 等（通过 polyfill）
- **代码优化**：移除未使用的代码

#### 2.2 Babel 的三阶段流程

**阶段 1：Parse（解析）**

把源代码转换成 **AST（抽象语法树）**：

```javascript
// 源代码
const name = 'Tom';

// AST（简化版）
{
  type: "VariableDeclaration",
  declarations: [{
    type: "VariableDeclarator",
    id: { type: "Identifier", name: "name" },
    init: { type: "StringLiteral", value: "Tom" }
  }],
  kind: "const"
}
```

**工具**：`@babel/parser`（基于 Acorn）

**阶段 2：Transform（转换）**

遍历 AST，应用插件进行转换：

```javascript
// 原始 AST
{
  type: "ArrowFunctionExpression",
  // ...
}

// 经过插件转换后
{
  type: "FunctionExpression",
  // ...
}
```

**工具**：`@babel/traverse`（遍历 AST）+ 各种插件（如 `@babel/plugin-transform-arrow-functions`）

**阶段 3：Generate（生成）**

把转换后的 AST 转换回 JavaScript 代码：

```javascript
// AST
{
  type: "FunctionExpression",
  // ...
}

// 生成的代码
function() { ... }
```

**工具**：`@babel/generator`

#### 2.3 完整流程示例

```javascript
// 源代码
const greet = (name) => `Hello, ${name}!`;

// 1. Parse：转换成 AST
const ast = parser.parse(code);

// 2. Transform：应用插件
traverse(ast, {
  ArrowFunctionExpression(path) {
    // 把箭头函数转换成普通函数
    path.replaceWith(/* 新的 AST 节点 */);
  }
});

// 3. Generate：生成代码
const output = generator(ast);

// 输出
const greet = function(name) {
  return "Hello, " + name + "!";
};
```

### 3. 手写 AST：去除 console 插件

#### 3.1 需求

写一个 Babel 插件，自动去除代码中的所有 `console.log`、`console.error` 等。

#### 3.2 实现思路

1. **遍历 AST**，找到所有 `console.xxx` 调用
2. **删除这些节点**

#### 3.3 完整代码

```javascript
const parser = require('@babel/parser');
const traverse = require('@babel/traverse').default;
const generator = require('@babel/generator').default;
const t = require('@babel/types');

// 源代码
const code = `
  function test() {
    console.log('hello');
    const a = 1;
    console.error('error');
    return a;
  }
`;

// 1. Parse：转换成 AST
const ast = parser.parse(code);

// 2. Transform：去除 console
traverse(ast, {
  // 访问所有表达式语句
  ExpressionStatement(path) {
    const { node } = path;
    
    // 检查是否是 console.xxx 调用
    if (
      t.isCallExpression(node.expression) &&
      t.isMemberExpression(node.expression.callee) &&
      t.isIdentifier(node.expression.callee.object, { name: 'console' })
    ) {
      // 删除这个节点
      path.remove();
    }
  }
});

// 3. Generate：生成代码
const output = generator(ast, {}, code);

console.log(output.code);
// 输出：
// function test() {
//   const a = 1;
//   return a;
// }
```

#### 3.4 关键点解释

**`t.isCallExpression`**：检查是否是函数调用
```javascript
console.log('hello') // ✅ 是 CallExpression
```

**`t.isMemberExpression`**：检查是否是成员表达式
```javascript
console.log // ✅ 是 MemberExpression
```

**`t.isIdentifier`**：检查是否是标识符
```javascript
console // ✅ 是 Identifier，name 是 'console'
```

**`path.remove()`**：删除当前节点

#### 3.5 封装成 Babel 插件

```javascript
// babel-plugin-remove-console.js
module.exports = function({ types: t }) {
  return {
    visitor: {
      ExpressionStatement(path) {
        const { node } = path;
        
        if (
          t.isCallExpression(node.expression) &&
          t.isMemberExpression(node.expression.callee) &&
          t.isIdentifier(node.expression.callee.object, { name: 'console' })
        ) {
          path.remove();
        }
      }
    }
  };
};
```

**使用**：

```javascript
// .babelrc
{
  "plugins": ["./babel-plugin-remove-console.js"]
}
```

### 4. Vite vs Webpack：核心差异总结

| 特性 | Webpack | Vite |
|------|---------|------|
| **冷启动** | 需要打包所有模块（慢） | 利用 ESM，按需转换（快） |
| **HMR** | 重新打包依赖链（慢） | 只转换变化的文件（快） |
| **生产构建** | 使用 Webpack 打包 | 使用 Rollup 打包（更优化） |
| **适用场景** | 大型项目，需要复杂配置 | 现代项目，追求开发体验 |

**面试表达**：
> "Vite 的核心优势是利用浏览器原生的 ESM 能力，不需要预先打包，实现了秒级冷启动。同时，HMR 只更新变化的文件，实现了毫秒级热更新。生产环境使用 Rollup 打包，保证了构建产物的优化。"

## Day 14 - 极致性能优化（秒开与流畅）(3.18，周三，3h)

> **今日策略**：深入理解浏览器渲染链路和性能指标，这是大厂面试的高频考点。掌握 CRP 优化和 Lighthouse 指标，能够量化性能提升。

### 1. CRP（关键渲染路径）优化：从 URL 到像素的完整链路

#### 1.1 什么是关键渲染路径（Critical Rendering Path）？

**定义**：从浏览器接收 HTML、CSS、JavaScript 字节，到将这些字节转换为屏幕上像素的完整过程。

**完整流程（6 个步骤）**：

```
1. 构建 DOM 树（Parse HTML）
   ↓
2. 构建 CSSOM 树（Parse CSS）
   ↓
3. 合并成渲染树（Render Tree）
   ↓
4. 布局（Layout / Reflow）- 计算元素位置和大小
   ↓
5. 绘制（Paint）- 填充像素
   ↓
6. 合成（Composite）- 将图层合并成最终图像
```

#### 1.2 阻塞渲染的资源

**CSS 是渲染阻塞资源**：
- 浏览器必须等待 CSS 下载并解析完成，才能构建渲染树
- **为什么？** 因为 CSS 会影响 DOM 的样式，浏览器不知道如何渲染元素
- **优化策略**：
  - 内联关键 CSS（Critical CSS）
  - 异步加载非关键 CSS（`<link rel="preload">` + `onload` 切换）

**JavaScript 是解析阻塞资源**：
- 当浏览器遇到 `<script>` 标签时，会**暂停 HTML 解析**，下载并执行 JavaScript
- **为什么？** 因为 JS 可能会修改 DOM，浏览器必须等待
- **优化策略**：
  - 使用 `async`：异步下载，下载完成后立即执行（不阻塞 HTML 解析）
  - 使用 `defer`：异步下载，等待 HTML 解析完成后再执行（按顺序执行）

**`async` vs `defer` 的区别**：

```html
<!-- async：下载完就执行，执行顺序不确定 -->
<script async src="a.js"></script>
<script async src="b.js"></script>
<!-- 可能 b.js 先执行完 -->

<!-- defer：HTML 解析完再执行，按顺序执行 -->
<script defer src="a.js"></script>
<script defer src="b.js"></script>
<!-- 保证 a.js 先执行 -->
```

#### 1.3 优化策略总结

**1. 减少关键资源数量**
- 延迟加载非关键 CSS
- 使用 `async`/`defer` 加载非关键 JS

**2. 减少关键资源大小**
- 压缩 CSS/JS（Gzip、Brotli）
- 移除未使用的 CSS（PurgeCSS）
- Tree-shaking 移除未使用的 JS

**3. 缩短关键路径长度**
- 内联关键 CSS
- 减少 HTTP 请求（合并文件、使用 HTTP/2）

### 2. GPU 合成层（Composite）加速机制与坑点

#### 2.1 什么是合成层？

**定义**：浏览器会把页面分成多个图层（Layer），每个图层独立渲染，最后合成（Composite）成最终图像。

**为什么需要合成层？**
- **性能优化**：只重绘变化的图层，而不是整个页面
- **硬件加速**：利用 GPU 并行处理多个图层

#### 2.2 什么情况下会创建合成层？

**触发条件（常用）**：
1. `transform: translateZ(0)` 或 `will-change: transform`（强制开启硬件加速）
2. `position: fixed`（固定定位元素）
3. `opacity` 动画（透明度变化）
4. `video`、`canvas`、`iframe` 元素
5. 3D 变换（`transform: translate3d()`）

**代码示例**：

```css
/* 强制开启硬件加速 */
.animated {
  transform: translateZ(0); /* 或 will-change: transform */
  transition: transform 0.3s;
}

.animated:hover {
  transform: translateX(100px); /* GPU 加速，性能更好 */
}
```

#### 2.3 合成层的坑点

**坑点 1：过度创建合成层导致内存占用过高**
- 每个合成层都会占用 GPU 内存
- 如果创建太多合成层，会导致内存溢出，反而变慢

**坑点 2：合成层之间的重绘**
- 如果父元素创建了合成层，子元素也会被提升到合成层
- 子元素的变化会导致整个合成层重绘

**最佳实践**：
- 只在需要动画的元素上使用 `transform` 和 `opacity`
- 避免在大量元素上使用 `will-change`
- 使用 Chrome DevTools 的 Layers 面板检查合成层数量

### 3. 新一代性能指标：Lighthouse 核心指标

#### 3.1 四大核心指标（Core Web Vitals）

**1. LCP（Largest Contentful Paint）- 最大内容绘制**

**定义**：页面最大内容元素（图片、视频、文本块）渲染完成的时间。

**测量方式**：
- 浏览器会持续监控页面，记录最大的内容元素
- 当这个元素渲染完成时，记录时间戳

**优化策略**：
- 优化图片加载（懒加载、WebP 格式、CDN）
- 优化字体加载（`font-display: swap`）
- 减少服务器响应时间（SSR、CDN）

**2. FCP（First Contentful Paint）- 首次内容绘制**

**定义**：浏览器首次渲染任何文本、图片、非白色 canvas 或 SVG 的时间。

**与 LCP 的区别**：
- FCP：第一个内容出现的时间（可能很小）
- LCP：最大内容出现的时间（用户真正看到主要内容）

**3. CLS（Cumulative Layout Shift）- 累积布局偏移**

**定义**：页面在加载过程中，元素位置发生意外移动的程度。

**计算方式**：
```
CLS = Σ（影响范围 × 移动距离）
```

**常见原因**：
- 图片没有设置 `width` 和 `height`，加载后撑开布局
- 字体加载延迟，导致文本位置变化
- 动态插入内容（广告、弹窗）

**优化策略**：
- 图片设置固定尺寸：`<img width="100" height="100">`
- 使用 `font-display: swap` 或预加载字体
- 为动态内容预留空间

**4. INP（Interaction to Next Paint）- 交互到下次绘制**

**定义**：用户交互（点击、输入、键盘）到浏览器能够响应并绘制下一帧的时间。

**测量方式**：
- 记录所有用户交互的延迟时间
- 取第 98 百分位的值（排除极端情况）

**优化策略**：
- 减少 JavaScript 执行时间（代码分割、懒加载）
- 使用 Web Workers 处理耗时任务
- 优化事件处理（防抖、节流）

#### 3.2 `PerformanceObserver` 采集原理

**什么是 PerformanceObserver？**

浏览器提供的 API，用于监听性能指标的变化。

**使用示例**：

```javascript
// 监听 LCP
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log('LCP:', entry.renderTime || entry.loadTime);
  }
});

observer.observe({ entryTypes: ['largest-contentful-paint'] });

// 监听 CLS
const clsObserver = new PerformanceObserver((list) => {
  let clsValue = 0;
  for (const entry of list.getEntries()) {
    if (!entry.hadRecentInput) {
      clsValue += entry.value;
    }
  }
  console.log('CLS:', clsValue);
});

clsObserver.observe({ entryTypes: ['layout-shift'] });
```

**实际应用**：
- 前端监控 SDK 使用 `PerformanceObserver` 采集性能数据
- 上报到服务器，用于性能分析和优化

## Day 15 - 海量数据与网络底层 (3.19，周四，3h)

> **今日策略**：把“列表卡顿”和“网络慢”这两类高频线上问题一次吃透。你要能从渲染机制、数据结构、协议层面给出可落地方案，而不是只会说“做个分页”。

### 1. 海量数据渲染：从“10 万条卡死”到“丝滑滚动”

#### 1.1 为什么 10 万条列表会卡？

根因有三层：
1. **DOM 节点太多**：浏览器要维护大量节点，内存和布局计算成本暴涨。
2. **频繁重排重绘**：滚动或筛选时触发大量 Layout/Paint。
3. **主线程被长任务占满**：JS 计算、Diff、渲染都挤在主线程，交互被阻塞。

#### 1.2 虚拟列表（Virtual List）的核心思想

虚拟列表不是“减少数据量”，而是“减少同一时刻在 DOM 里的节点数”。

**核心策略**：
- 数据仍然是 10 万条；
- DOM 只渲染“视口内 + 缓冲区”的几十条；
- 随滚动动态替换可见节点；
- 通过占位容器保持滚动条高度正确。

**简化结构**：

```html
<div class="viewport">
  <div class="phantom"></div>   <!-- 撑起总高度 -->
  <div class="list"></div>      <!-- 只放可见项 -->
</div>
```

#### 1.3 固定高度虚拟列表实现（高频面试版）

```javascript
const itemHeight = 40;
const buffer = 5; // 上下缓冲，避免白屏

function calcRange(scrollTop, viewportHeight, total) {
  const visibleCount = Math.ceil(viewportHeight / itemHeight);
  let start = Math.floor(scrollTop / itemHeight) - buffer;
  start = Math.max(start, 0);
  let end = start + visibleCount + buffer * 2 - 1;
  end = Math.min(end, total - 1);
  return { start, end };
}

function getOffsetY(start) {
  return start * itemHeight;
}
```

**面试表达**：
> “固定高度场景下，虚拟列表的本质是用 scrollTop 算 start/end 索引，再把可见区数据映射成少量 DOM。复杂度从维护 10 万节点，变成维护几十节点。”

#### 1.4 动态高度虚拟列表（进阶）

动态高度难点在于：无法直接用 `scrollTop / itemHeight` 求索引。

常见方案：
1. **高度缓存表**：渲染后测量每项高度，写入 map。
2. **前缀和数组**：维护每个索引前累计高度。
3. **二分查找**：根据 scrollTop 在前缀和里查 startIndex。

```javascript
// prefixHeights[i] = 0..i 的累计高度
function findStartIndex(scrollTop, prefixHeights) {
  let l = 0, r = prefixHeights.length - 1;
  while (l < r) {
    const m = (l + r) >> 1;
    if (prefixHeights[m] < scrollTop) l = m + 1;
    else r = m;
  }
  return l;
}
```

### 2. 时间分片（Time Slicing）处理重计算

当一次计算很重（如本地筛选 10 万数据），可把任务切片，避免主线程长时间阻塞。

```javascript
function chunkProcess(list, handler, chunk = 200) {
  let i = 0;
  function run() {
    const end = Math.min(i + chunk, list.length);
    while (i < end) handler(list[i++]);
    if (i < list.length) {
      // 让出主线程，下一帧继续
      requestAnimationFrame(run);
    }
  }
  requestAnimationFrame(run);
}
```

**区别点**：
- 虚拟列表：优化 **渲染成本**（DOM 数量）。
- 时间分片：优化 **计算成本**（JS 长任务）。

### 3. 网络进阶：HTTP/2 与 HTTP/3 面试必答

#### 3.1 HTTP/1.1 痛点

- 队头阻塞（Head-of-Line Blocking）；
- 并发连接数受限（同域一般 6 个左右）；
- 请求头重复冗余。

#### 3.2 HTTP/2 三大核心优势

1. **多路复用（Multiplexing）**：
   一个 TCP 连接上并行传多个请求响应，减少连接开销。

2. **头部压缩（HPACK）**：
   通过静态/动态表压缩重复头字段，降低带宽。

3. **二进制分帧**：
   文本协议变成二进制帧，更高效、更易解析。

#### 3.3 HTTP/3（QUIC）为什么更快？

HTTP/3 基于 UDP + QUIC，核心收益：
- **0-RTT / 1-RTT 握手**，建连更快；
- **连接迁移**（IP 变化不断连）；
- 解决 TCP 层队头阻塞（单包丢失不拖垮整连接流）。

### 4. 面试中的“海量数据”答题模板

> “我会分三层优化：第一层渲染层，用虚拟列表把 10 万 DOM 降到几十个；第二层计算层，用时间分片或 Worker 拆解长任务；第三层网络层，用分页/增量加载，并结合 HTTP/2 或 HTTP/3 降低传输时延。最后用 Performance 面板和 LCP/INP 指标量化结果。”

- ✅ **虚拟列表核心**：只渲染可视区，固定高度与动态高度两套方案
- ✅ **时间分片**：把长任务拆分到多帧执行，避免主线程阻塞

- ✅ **面试表达**：渲染层 + 计算层 + 网络层三段式优化

### 3. 大文件上传：切片 + 断点续传 + 秒传

#### 3.1 切片上传流程

1. 前端用 `File.slice` 切片；

3. 服务端合并切片；
4. 返回最终文件地址。

```javascript
function createChunks(file, size = 2 * 1024 * 1024) {
  const chunks = [];
  let cur = 0;
```

## Day 18 - 复杂算法突击（一）(3.22，周日，5h)

### 1. 数据结构速通：数组、链表、栈、队列、哈希表

#### 1.1 数组 vs 链表（面试常问）

- **数组**：随机访问 `O(1)`，中间插入删除 `O(n)`。
- **链表**：随机访问 `O(n)`，已定位节点后插删 `O(1)`。

面试表达：
> “读多改少偏数组；频繁插删、且位置已知偏链表。”

#### 1.2 栈与队列

- **栈（Stack）**：LIFO，常用于括号匹配、函数调用栈。
- **队列（Queue）**：FIFO，常用于 BFS、任务调度。

#### 1.3 哈希表

- 平均 `O(1)` 查找/插入；
- 关键是 **哈希函数 + 冲突处理**（链地址法/开放寻址）；
- JS 里常用 `Map` 实现。

### 2. 排序与查找

#### 2.1 快速排序（必须会写）

```javascript
function quickSort(arr) {
  if (arr.length <= 1) return arr;
  const pivot = arr[Math.floor(arr.length / 2)];
  const left = [], mid = [], right = [];
  for (const x of arr) {
    if (x < pivot) left.push(x);
    else if (x > pivot) right.push(x);
    else mid.push(x);
  }
  return [...quickSort(left), ...mid, ...quickSort(right)];
}
```

复杂度：
- 平均 `O(n log n)`；
- 最坏 `O(n^2)`（极端有序 + 不好枢轴）。

#### 2.2 归并排序（稳定）

```javascript
function mergeSort(arr) {
  if (arr.length <= 1) return arr;
  const mid = arr.length >> 1;
  return merge(mergeSort(arr.slice(0, mid)), mergeSort(arr.slice(mid)));
}

function merge(a, b) {
  const res = [];
  let i = 0, j = 0;
  while (i < a.length && j < b.length) {
    res.push(a[i] <= b[j] ? a[i++] : b[j++]);
  }
  return res.concat(a.slice(i), b.slice(j));
}
```

复杂度：
- 时间 `O(n log n)`；
- 空间 `O(n)`。

#### 2.3 二分查找与变种

标准模板：

```javascript
function binarySearch(nums, target) {
  let l = 0, r = nums.length - 1;
  while (l <= r) {
    const m = l + ((r - l) >> 1);
    if (nums[m] === target) return m;
    if (nums[m] < target) l = m + 1;
    else r = m - 1;
  }
  return -1;
}
```

变种高频：
- 第一个等于 target；
- 最后一个等于 target；
- 第一个大于等于 target（lower_bound）。

### 3. 链表进阶

#### 3.1 反转链表（迭代）

```javascript
function reverseList(head) {
  let prev = null, cur = head;
  while (cur) {
    const next = cur.next;
    cur.next = prev;
    prev = cur;
    cur = next;
  }
  return prev;
}
```

#### 3.2 判断链表是否有环（快慢指针）

```javascript
function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true;
  }
  return false;
}
```

#### 3.3 合并 K 个升序链表（最小堆思路）

面试重点先说思路：
1. 把每条链表头节点放入最小堆；
2. 弹出最小节点挂到结果链表；
3. 若该节点有 next，则 next 入堆；
4. 循环直到堆空。

复杂度：`O(N log K)`，N 为总节点数，K 为链表个数。

```javascript
function levelOrder(root) {
  if (!root) return [];

  while (q.length) {
    const size = q.length;
    const level = [];
    for (let i = 0; i < size; i++) {
      const node = q.shift();
      level.push(node.val);
      if (node.left) q.push(node.left);
      if (node.right) q.push(node.right);

    ans.push(level);

}
```

#### 1.2 最近公共祖先（LCA，二叉树）

```javascript
function lowestCommonAncestor(root, p, q) {
  if (!root || root === p || root === q) return root;
  const left = lowestCommonAncestor(root.left, p, q);
  const right = lowestCommonAncestor(root.right, p, q);
  if (left && right) return root;
  return left || right;
}
```

#### 1.3 二叉树路径和（Path Sum）

```javascript
function hasPathSum(root, targetSum) {

  if (!root.left && !root.right) return targetSum === root.val;
  return (
    hasPathSum(root.left, targetSum - root.val) ||
    hasPathSum(root.right, targetSum - root.val)

}
```

```javascript
function lengthOfLongestSubstring(s) {

  const map = new Map();
  for (let r = 0; r < s.length; r++) {
    const ch = s[r];
    if (map.has(ch) && map.get(ch) >= l) l = map.get(ch) + 1;
    map.set(ch, r);
    ans = Math.max(ans, r - l + 1);
  }
  return ans;
}
```

#### 2.2 三数之和（排序 + 双指针）

```javascript
function threeSum(nums) {
  nums.sort((a, b) => a - b);
  const res = [];
  for (let i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] === nums[i - 1]) continue;
    let l = i + 1, r = nums.length - 1;
    while (l < r) {
      const sum = nums[i] + nums[l] + nums[r];
      if (sum === 0) {
        res.push([nums[i], nums[l], nums[r]]);
        while (l < r && nums[l] === nums[l + 1]) l++;
        while (l < r && nums[r] === nums[r - 1]) r--;
        l++; r--;
      } else if (sum < 0) l++;
      else r--;
    }
  }
  return res;
}
```

## Day 20 - 动态规划与经典大厂题 (3.24，周二，3h)

> **今日策略**：Day 20 开始进入第四阶段题型，但先补你要的“三天内容”。今天重点是 DP 的状态定义能力 + LRU 手写这个高频硬题。

### 1. 动态规划三连

#### 1.1 打家劫舍（House Robber）

状态定义：
- `dp[i]`：抢到第 i 间房时，前 i 间的最大收益。

转移：
- 不抢 i：`dp[i-1]`
- 抢 i：`dp[i-2] + nums[i]`
- 取最大。

```javascript
function rob(nums) {
  if (!nums.length) return 0;
  if (nums.length === 1) return nums[0];
  let prev2 = nums[0];
  let prev1 = Math.max(nums[0], nums[1]);
  for (let i = 2; i < nums.length; i++) {
    const cur = Math.max(prev1, prev2 + nums[i]);
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}
```

#### 1.2 零钱兑换（Coin Change）

```javascript
function coinChange(coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (let i = 1; i <= amount; i++) {
    for (const c of coins) {
      if (i >= c) dp[i] = Math.min(dp[i], dp[i - c] + 1);
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

#### 1.3 最长回文子串（中心扩展）

```javascript
function longestPalindrome(s) {
  if (s.length < 2) return s;
  let start = 0, maxLen = 1;
  const expand = (l, r) => {
    while (l >= 0 && r < s.length && s[l] === s[r]) { l--; r++; }
    const len = r - l - 1;
    if (len > maxLen) {
      maxLen = len;
      start = l + 1;
    }
  };
  for (let i = 0; i < s.length; i++) {
    expand(i, i);
    expand(i, i + 1);
  }
  return s.slice(start, start + maxLen);
}
```

### 2. 经典手写：LRU 缓存（Map 版）

```javascript
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map();
  }

  get(key) {
    if (!this.map.has(key)) return -1;
    const val = this.map.get(key);
    this.map.delete(key);
    this.map.set(key, val); // 刷新为最新
    return val;
  }

  put(key, value) {
    if (this.map.has(key)) this.map.delete(key);
    this.map.set(key, value);
    if (this.map.size > this.capacity) {
      const oldestKey = this.map.keys().next().value;
      this.map.delete(oldestKey);
    }
  }
}
```

复杂度：
- `get` / `put` 平均 `O(1)`。

#### 1.1 为什么要有 BFF？

前端直连多个后端常见问题：

### 2. 洋葱模型与 `compose` 手写

Koa 中间件是典型“洋葱模型”：先进后出。

```javascript
function compose(middlewares) {
  return function (ctx) {
    let index = -1;
    function dispatch(i) {
      if (i <= index) return Promise.reject(new Error('next() called multiple times'));
      index = i;
      const fn = middlewares[i];
      if (!fn) return Promise.resolve();
      return Promise.resolve(fn(ctx, () => dispatch(i + 1)));
    }
    return dispatch(0);
  };
}
```

面试表达：
> “洋葱模型保证了统一前置处理（鉴权、日志）和后置收口（错误处理、耗时统计）。”

### 3. Node 内存泄漏排查思路（高频）

#### 3.1 常见泄漏来源

- 全局变量意外持有；
- 缓存无淘汰策略；
- 定时器/事件监听未清理；
- 闭包长链引用；
- 大对象日志或队列积压。

#### 3.2 排查流程（可背）

1. **现象确认**：内存持续上涨、GC 后不回落；
2. **抓快照**：`heapdump` 导出快照；
3. **对比快照**：看 Retainers（引用链）和 Dominator；
4. **定位对象类型**：哪个类实例在持续增长；
5. **回溯代码**：找到持有引用未释放点；
6. **修复验证**：压测 + 监控看曲线回归。

### 4. 多进程与多线程（Node 视角）

- **多进程**：`cluster` / 多实例部署，提高 CPU 利用率与隔离性；

```javascript
// 指数退避重试（简化）
async function retry(fn, { times = 3, base = 300 }) {
  let attempt = 0;
  while (attempt < times) {
    try { return await fn(); }
    catch (e) {
      const delay = base * 2 ** attempt + Math.random() * 100;
      await new Promise(r => setTimeout(r, delay));
      attempt++;
    }
  }
  throw new Error('retry_exhausted');
}
```

### 2. 缓存体系：浏览器缓存 + 应用缓存 + CDN

```javascript
function deepClone(input, seen = new WeakMap()) {
  if (input === null || typeof input !== 'object') return input;
  if (seen.has(input)) return seen.get(input);
  if (input instanceof Date) return new Date(input.getTime());
  if (input instanceof RegExp) return new RegExp(input.source, input.flags);
  const out = Array.isArray(input) ? [] : Object.create(Object.getPrototypeOf(input));
  seen.set(input, out);
  for (const key of Reflect.ownKeys(input)) {
    out[key] = deepClone(input[key], seen);
  }
  return out;
}
```

#### 1.2 并发请求控制（带失败重试与取消）

```javascript
function createPool(limit = 4) {
  let active = 0;
  const queue = [];
  const run = async () => {
    if (active >= limit || queue.length === 0) return;
    active++;
    const { task, resolve, reject } = queue.shift();
    try { resolve(await task()); }
    catch (e) { reject(e); }
    finally { active--; run(); }
  };
  return function push(task) {
    return new Promise((resolve, reject) => { queue.push({ task, resolve, reject }); run(); });
  };
}
```

#### 1.3 事件总线（支持一次性监听 once）

```javascript
class EventBus {
  constructor() { this.map = new Map(); }
  on(evt, fn) { (this.map.get(evt) || this.map.set(evt, []).get(evt)).push(fn); }
  once(evt, fn) {
    const wrapper = (...args) => { this.off(evt, wrapper); fn(...args); };
    this.on(evt, wrapper);
  }
  off(evt, fn) {
    const arr = this.map.get(evt); if (!arr) return;
    const i = arr.indexOf(fn); if (i > -1) arr.splice(i, 1);
  }
  emit(evt, ...args) { (this.map.get(evt) || []).slice().forEach(fn => fn(...args)); }
}
```

#### 1.4 防抖/节流（立即触发选项）

```javascript
function debounce(fn, wait = 200, immediate = false) {
  let timer = null;
  return function(...args) {
    const callNow = immediate && !timer;
    clearTimeout(timer);
    timer = setTimeout(() => { timer = null; if (!immediate) fn.apply(this, args); }, wait);
    if (callNow) fn.apply(this, args);
  };
}

function throttle(fn, wait = 200, leading = true, trailing = true) {
  let last = 0, timer = null;
  return function(...args) {
    const now = Date.now();
    if (!last && !leading) last = now;
    const remain = wait - (now - last);
    if (remain <= 0) {
      if (timer) { clearTimeout(timer); timer = null; }
      last = now; fn.apply(this, args);
    } else if (trailing && !timer) {
      timer = setTimeout(() => { last = leading ? Date.now() : 0; timer = null; fn.apply(this, args); }, remain);
    }
  };
}
```

#### 1.5 Promise.all/any/allSettled（要点版）

```javascript
function all(iterable) {
  const arr = Array.from(iterable);
  if (arr.length === 0) return Promise.resolve([]);
  let count = 0; const res = new Array(arr.length);
  return new Promise((resolve, reject) => {
    arr.forEach((p, i) => Promise.resolve(p).then(v => {
      res[i] = v; if (++count === arr.length) resolve(res);
    }, reject));
  });
}
```
