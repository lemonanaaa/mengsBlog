| 项目 | 说明 |
|------|------|
| 目标公司 | **字节跳动**（优先）、阿里巴巴、腾讯 |

面试官通常关心：

- 复杂问题如何 **拆解**，是否有 **数据或事实** 支撑结论。
- 线上问题能否 **系统排查**（工具链、监控、复现路径），而非仅凭感觉。
- 技术方案能否说明 **为何不是 B/C 而选 A**（权衡取舍）。

**准备重心**：项目叙事 + 原理深度 + 编码稳定输出，而非单纯扩大「八股」覆盖面。

## 二、6.7 首面前的压缩策略

> 两周冲刺不能按 8～12 周计划等比例缩短，必须保面试产出。

### 1. 时间优先级

| 优先级 | 内容 | 目标 |
|--------|------|------|
| P0 | 简历项目、手写、算法、React、性能/工程化 | 首面不露短板，能被追问 |
| P1 | 网络安全、TS、开放场景、AI 辅助开发 | 补常见追问和加分项 |
| P2 | Vue3 深水区、Node/BFF、微前端、HTTP/3、复杂 TS 体操 | 只准备概念和边界 |

### 2. 每天必须产出的东西

- **1 个可复述产物**：项目故事、技术专题、开放题方案三选一，必须能 3 分钟讲清。
- **1 个闭卷编码产物**：算法或手写，写完补边界、复杂度、测试用例。
- **1 个错点记录**：只记当天最可能在面试中被问倒的点，第二天先补。

### 3. 首面前最低通过线

- 自我介绍 2 分钟内稳定，能自然引到 2-3 个核心项目。
- 任意一个核心项目能连续回答：为什么做、你做了什么、难点、备选方案、指标、风险、复盘。
- 手写题能先讲思路再编码，不沉默硬写；写完能主动补边界。
- React、性能、工程化至少各有一个贴简历的例子。
- 不会的问题能说明理解边界和排查/学习路径，不硬编线上经验。

## 三、大厂前端近年高频方向（总览）

下列为近年面经与社区文章中反复出现的模块，准备时可作 **查漏清单**。

### 1. JavaScript / 运行时

- 异步：Event Loop、宏任务/微任务、`async/await` 与 Promise、常见输出题。
- 手写：`Promise.all` / `race` / `allSettled`、防抖/节流、深拷贝、`call`/`apply`/`bind`、`new`、简易 `instanceof` 等。
- 语言与 API：闭包、作用域、`this`、类型判断、`Proxy`/`Reflect`（常与 Vue3、响应式一起问）。

### 2. 框架深度（按简历主栈）

- **React**：Fiber、协调与 key、`memo`/`useMemo`/`useCallback`、Hooks 与闭包坑、React 18 自动批处理/并发特性、RSC/App Router 相关概念（问法因团队而异）。
- **Vue**：Vue3 响应式（`Proxy` vs Vue2）、`computed` vs `watch`、更新与编译相关原理题。

### 3. 浏览器与网络

- 从输入 URL 到渲染（可深可浅）。
- HTTP/HTTPS、缓存、跨域、WebSocket / SSE。
- 安全：XSS、CSRF、Cookie（如 `SameSite`）、CSP 等（常与场景结合）。

### 4. 工程化与构建

- Webpack / Vite、打包与 `chunk`、Tree Shaking 在考什么。
- CJS vs ESM 及对打包、加载的影响。
- 微前端：隔离、通信、适用场景（中高级常见）。

### 5. 性能与体验

- Core Web Vitals、如何度量与优化。
- 长列表/大数据：虚拟列表、分片渲染、`requestIdleCallback` 等思路。
- 首屏、白屏、包体积：代码分割、懒加载、资源策略。
- 监控与排查：白屏、长任务、错误上报（可能涉及 `sendBeacon`、关闭页前发送数据等），以及“发现 -> 定位 -> 回滚/修复 -> 防复发”的闭环。

### 6. 场景题 / 开放题（权重上升）

常见类型：大文件分片上传与断点续传、请求并发/限流、埋点与页面关闭、电梯导航、拖拽、防重复提交、SSO、静态资源失败降级等。  
考察 **思路是否完整、能否权衡方案**，而非只背定义。

### 7. 中高级：前端「系统设计」

例如：带防抖/缓存的搜索联想、通知中心、无限滚动信息流、复杂表单与状态管理。  
需能讨论：状态放哪里、网络次数、扩展性、性能。

### 8. 算法与手写

- 不少国内大厂仍考 **LeetCode 风格**（难度因厂因岗而异）。
- 另有 **纯前端手写**（与上文 JS 手写重叠），可能与算法分场进行。

### 趋势简述

纯背诵仍在，但越来越多面试把 **场景排查、性能、工程化权衡、项目深挖** 绑在一起；**TypeScript**、**RSC/现代构建** 在 React 栈中出现频率上升。

## 四、字节前端（社招）：建议权重

以下为近年多篇字节前端 **社招** 面经中的共性归纳，**不同部门差异仍可能很大**，仅作备考优先级参考。

| 维度 | 说明 |
|------|------|
| **简历与项目** | 从简历追问到底：背景 → 职责 → 难点 → 方案对比 → 结果（最好有指标）。部分业务会问英语、团队角色、业务理解。 |
| **编码** | **前端手写**出现频率高：Promise 系列、防抖节流、深拷贝、柯里化、带 **超时/重试** 的请求、**异步任务调度器** 等；需能讲清边界与变式。算法上多反馈 **LeetCode 中等** 为主，但 **算法轮次与难度因部门差异大**，建议 **中等为主 + 少量 Hard** 防身。 |
| **基础到原理** | Event Loop、异步输出题、`this`、跨域（含 **Nginx 代理 vs CORS** 等对比）、性能与大列表/大数据量实践。 |
| **工程化** | **Webpack vs Vite**、构建与体验、**Web Worker** 适用场景等。 |
| **近年加分/常问** | 工作中 **AI 使用**、如何审 AI 生成代码、Prompt/D2C/Agent 的 **真实、克制** 表述（不必夸大）。 |
| **软技能与 HR** | 职业规划、离职原因、工作强度与学习方式；协作推动难案例。字节节奏快、追问深，**每个简历 bullet 能展开约 5 分钟** 往往比盲目刷散题更划算。 |

### 口径校准

- Fiber：强调“可中断 Render + 同步 Commit”，不要泛化成“React 更新都是异步”。
- `useEffect`：强调 Passive Effect 通常在绘制后执行，不要简单归类为宏任务/微任务。
- Tree Shaking：强调 ESM 静态结构只是前提，还需要副作用标记和压缩阶段配合。
- 闭包：强调延长生命周期，不等同于必然泄漏。
- 项目指标：所有数字都准备统计口径，不能解释的数字宁可降级成定性表述。

## 五、阿里、腾讯：相对字节的微调

- **阿里巴巴**：同样重视 **项目深度与业务结果**；岗位与 BU 匹配度重要。风格因 BU 而异，但 **难点、数据、协作** 是共通叙事重点。
- **腾讯**：部分业务线 **开场算法/做题** 压力可能更大，建议 **算法强度略高于「仅按字节准备」的最低线**；简历需有清晰亮点，避免「题会做但经历撑不住」。

**策略**：主准备按 **字节（项目深挖 + JS 手写 + 中等算法）**，阿里腾讯 **共用同一套底盘**；若重点投腾讯，**单独加大算法练习量**。

## 六、四条主线（建议贯穿始终）

1. **2～3 个项目主轴**  
   每个准备：**业务一句话 → 架构（心中有图）→ 最难 1～2 点 → 方案对比 → 指标**（性能、效率、稳定性、成本）。  
   提前准备：**团队定位、推动协作不畅时的真实案例**（技术面与 HR 均可能问）。

2. **手写与运行时**  
   闭卷能写且能口述：Promise 静态方法、并发/串行控制、防抖节流、深拷贝、调度器、简易 `get`/`bind` 等；Event Loop 与输出题能 **画图推演**，不凭感觉猜。

3. **算法**  
   以 **中等** 为主（数组、哈希、双指针、二叉树、DFS/BFS、基础 DP），保持周更手感；投腾讯向可适当加 Hard 抽样。

4. **工程化与性能**  
   与仓库 **《第三阶段-工程化性能优化与大型基建》** 对齐：首屏、长列表、包体、监控、异常与灰度、微前端等——**做过讲透，没做过诚实说明 + 学习/落地思路**，避免硬编。

## 七、8～12 周节奏（可按离职窗口压缩）

| **投递后** | 保持 **算法手感**；**每轮复盘** 补洞，动态调整。 |

## 附录：在职 · 2026 年 4 月冲刺（自定义时间块）

> 目标：**4 月底前达到「可以开始投递/约面试」**（见上文第八章检查清单），而非当月必须拿 offer。  
> 以下按你提供的时间窗口排版；若某日加班或状态差，优先保 **「项目叙事 + 中等算法 + 一类手写」**，其余顺延。

### 1. 你的固定时间块（用于对照）

| 时段 | 长度 | 性质 |
|------|------|------|
| 工作日 **7:30～10:00** | **2.5h** | 整段专注（算法 / 手写 / 框架与项目深挖） |
| 工作日 **14:00～15:30** | **1.5h** | 短段巩固（输出题、复盘、小题、简历 bullet） |
| 周末 **15:00～22:00 内** | **约 5h/天**（含休息） | 模拟面试、长项目复盘、补弱项 |

两段时间合计 **4h/工作日**；若你只能稳定落实其中 **3h**，按「保底 3h」理解即可，下面总学时给出区间。

### 2. 2026 年 4 月剩余可备考窗口（自 4/11 起）

- **4 月 11 日（六）～ 4 月 30 日（四）** 共 **20 天**（含首尾）。  
- 其中 **工作日 14 天**、**周末 6 天**。

**粗算总净学时**（仅作压力参考）：

- 若工作日按满 **4h**、周末 **5h**：\(14×4 + 6×5 = 86\) **小时**。  
- 若工作日只按 **3h**、周末 **5h**：\(14×3 + 6×5 = 72\) **小时**。

这个量级对「开面就绪」是 **够用的**，前提是 **少做无效收藏、少刷散题**，把小时堆在 checklist 上。

### 3. 时间块怎么用（工作日模板）

| 块 | 建议主用途（字节优先） |
|----|------------------------|
| **早 2.5h** | **二选一为主**：① **LeetCode 中等 1～2 道**（含订正）或 ② **手写题闭卷**（Promise 系列 / 防抖节流 / 深拷贝 / 带超时重试的 fetch / 调度器）+ 口述边界。状态好时可 **算法 1h + 手写 1～1.5h**。 |
| **午段 1.5h** | **输出题 / Event Loop** 小题 1～2 组；或订正上午错题；或 **简历上改 1 个 bullet**；或 **第二阶段** 中与主栈相关的一小节（不贪多）。 |

**原则**：整块早晨给 **最需要脑力** 的事；午段做 **短平快、可收尾** 的事，避免开大块源码。

### 4. 周末 5h 怎么用（模板）

| 块 | 建议 |
|----|------|
| **约 2～2.5h** | **模拟面试**：自我介绍 2min + 抽 **1 个项目**连续追问 25～35min + **1 道手写限时 25～35min**；或 **半套**：只练项目深挖。 |
| **约 2h** | **第三阶段** 中与经历匹配的章节（性能/构建/监控/微前端任一条线读透 + 用自己的话复述）。 |
| **约 0.5～1h** | 周复盘：本周错题、手写重练、下周只攻 **1～2 个短板**。 |

至少安排 **2 个周末各做一次完整或半套模拟**（例如 4/12～13、4/19～20、4/26～27 中选）。

### 5. 三阶段划分（对应 4/11～4/30）

| 阶段 | 日期（示例） | 重心 |
|------|----------------|------|
| **A 打底** | **4/11～4/17** | 简历定稿；每项目 **半页～1 页故事**；Event Loop + 异步输出题；手写 **至少 3 类**（如 Promise.all、防抖、深拷贝）；中等题 **每天 1 道**（订正算完成）。 |
| **B 强化** | **4/18～4/24** | 手写轮换 + 中等题 **每天 1～2**；主栈框架与简历项目 **绑定**（第二阶段摘 20% 最相关的）；第三阶段摘 **与经历相关** 的性能/工程化，能讲 **现象→手段→结果**。 |
| **C 开面前** | **4/25～4/30** | **模拟 + 短板**；职业规划/离职原因/**AI 使用** 各准备 3～5 分钟版；算法与手写 **保温**（每天少量）；**4/30 前** 自查第八章清单，勾选后可 **开始投递**。 |

### 6. 强度与心态（实话）

- 你当前节奏约 **每周 25～30 有效小时**，属于 **偏强的在职冲刺**，可持续到 **4 月底**，但需保证睡眠；若连续崩盘，宁可 **减广度**（少刷面经），**不减项目 + 算法 + 手写**。  
- **「准备好」的定义**：不是无死角，而是 **清单大部打勾 + 模拟过至少 1～2 次**；剩余细节 **边投边补** 完全正常。

### 7. 崩盘时的最小保底（单日）

若某天只能 **1h**：**半道中等订正 + 1 个手写函数默写 + 1 个简历 bullet 口头过一遍**。  
若某天 **0**：次日早晨优先 **补昨天错题**，不要叠加新题。
